# 15분 환경 체험

목표는 큰 앱을 만드는 것이 아니라 **문서 읽기 → 계획 → 작은 실행 → 검증 기록**이 이 환경에서 가능한지 확인하는 것입니다. 환경의 실제 안내가 우선합니다. 체험 시작, 감독 동의, 제출은 사용자가 직접 합니다.

## 0–3분: 가져오기와 읽기

허용된 터미널에서 프로젝트 폴더로 이동하고 README의 clone 명령을 실행합니다. clone이 실패하면 오류를 확인하고, 허용된 문서 다운로드 경로가 있는 경우만 사용합니다. 개인 인증이나 환경 설정 변경으로 우회하지 않습니다.

에이전트에 요청:

```text
hha/guidance.md를 읽어줘. 지금은 15분 환경 체험이야.
현재 작업 경로와 제공 런타임, 파일 읽기/쓰기, 허용된 실행 방법부터 확인해.
제공된 연습 과제가 있으면 그것을 사용하고, 없으면
hha/examples/empty-project/README.md를 읽어 허용된 별도 연습 폴더에서 진행해.
하네스 폴더와 원본 예제 README는 수정하지 마.
업데이트, 외부 전송, UI 자동 조작, 추가 AI 세션은 하지 마.
```

## 3–6분: SPEC과 검증 초안

```text
필수 요구사항을 체크리스트형 SPEC으로 만들고 중요한 미정 사항만 질문해.
README와 SPEC을 넣어 프로젝트 전용 검증 스킬 초안을 만들어줘.
아직 없는 명령이나 구현을 존재하는 것처럼 적지 마.
```

확인할 것: 요구사항이 빠지지 않았는지, 구현 체크와 검증 체크가 분리됐는지, 빈 프로젝트를 실패로 취급하지 않는지.

## 6–12분: 하나의 작은 경로

```text
가장 작은 필수 경로 하나를 구현하고 검증 절차를 실제 코드에 맞춰 확정해.
정상 입력과 잘못된 입력을 실행해 결과를 기록해.
제공 런타임이 없으면 설치에 시간을 쓰지 말고 막힌 지점을 알려줘.
```

## 12–15분: 기록과 정리

```text
실제로 확인한 것과 확인하지 못한 것을 나눠줘.
SPEC 상태와 증거가 일치하는지 확인하고 네가 시작한 임시 프로세스만 정리해.
다음 세션에서 읽을 파일 경로와 다음 할 일을 짧게 남겨줘.
```

기록할 환경 정보: 런타임과 버전, 작업 경로, clone 가능 여부, 실행 명령, 오류와 제한. UI 기능이 필요하다면 제공된 수동 미리보기 경로도 사용자가 확인합니다. 비밀 값이나 개인 링크는 기록하지 않습니다. 체험 성공이 본 작업의 모든 기능이나 도구 사용 허용을 보장하지는 않습니다.
